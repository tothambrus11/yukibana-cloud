Yukibana design system: headers

Your notes on the first proof, applied. Cloud has its own header and tables whose rows are links with checkboxes for bulk actions; Light's tabs now match round 7 exactly; the docs keep patterns out from behind text; the landing page leads with the logo and the current site's words. Six backgrounds to compare. Four real screens: the landing page, a docs article, a cloud edition page and the Light editor. This is the check before I write it down as tokens. Judge each screen as a whole, in both themes.

The system so far

CharacterCool, engineered, welcoming to beginners, slightly serious, of its moment. To the point; never bloated.
TypeBricolage Grotesque for headings, Atkinson Hyperlegible Next for text, JetBrains Mono without ligatures for code.
ColourCool blue-grey greys and Light's green as the one accent, in light and dark. Every pair passes WCAG AA.
ShapeRounded: small flat pill buttons, tinted chips with an icon for states, 8px corners on fields and panels, no 3D or glow.
TabsUnderline for pages. Tables: rows are links, checkboxes for bulk actions. In Light: short dividers, the current tab in the editor colour on a darker bar, green line only where you type.
SignatureA pattern in side rails, gutters and the landing hero, never behind text or in headers. Which pattern is open below. No colour stripe on top.

Why Yukibana?

Professional IDEs are built to make experts fast. For a beginner, the same help can do the thinking for them, and the setup can take the first week. Yukibana puts fruitful friction back where it helps learning, and removes the sterile friction that does not. Read more

Features that grow with the course

Start from a text editor and a run button. Turn on error underlines, code suggestions or AI assistance when the course is ready for them.

Simple setup

One installer. Each exercise opens from a link, with its instructions, the right files, a real build and its tests.

AI on your terms

AI assistance is a switch the teacher holds, per exercise. Yukibana does not decide how your course uses AI; it lets you decide.

Hand-in is a button

Students submit from the toolbar and see exactly which files are sent. Late work is accepted and marked, never lost.

Hidden tests, protected files

Hidden tests never reach students. Read-only files are put back at grading time, and every change to them is reported.

Publish from Git

An exercise is a repository with a yukibana.json. Publish it with the CLI, or on every push with the GitHub Action.

I am a student

Open an exercise from the cloud, work on it, and hand it in.

I am a teacher

Turn a course repository into an exercise, set its dates, and collect submissions ready to grade.

States and components, round 3

Two things left before the system is written down as tokens: the code block, combined from your notes, and messages, where success and error must look like one family. Everything else from rounds 1 and 2 is in the list below.

FocusThe ink ring: black in the light theme, white in dark, 2 px with a gap. Green stays for actions.
FieldsOutlined, with the label on top. Settings pages on a wide screen may put the label beside, and fall back to on top on phones.
Notes in the docsTinted box with the icon in its own column, blue for a note, amber for a warning.
IconsThin outline, stroke 1.5, Lucide style.
DeletingA dialog for things that cannot come back. Wherever the server can keep it, delete at once and offer Undo; your note says Undo should always be possible, so the cloud keeps deleted rows for a while instead of removing them.
Empty listsCentred, a small fading patch of the triangles, a title, one sentence and the button.
It workedWhere it fits, the button says so itself. Otherwise a message, styled like the error messages below.
WaitingSkeleton rows for content that is coming, a spinner for small things such as a button or a single panel.
MotionQuick fades, 120 ms, no movement. Tabs turn bold in place: each label reserves its bold width, so nothing shifts (switch the tabs in question 2).

Ten headers, second generation

Built from your notes: capped width for the lifted bar, a minimum width for the pill, the divided bar without the box-in-a-box search, and the filled GitHub mark. Hanging tab, two rows and centred logo are out. As before, what goes in them: sections are Docs, Playground (Light in the browser) and Embed (Light as a component for other sites, its own audience), plus GitHub. Actions: Sign in everywhere for returning students and teachers, and nothing else: the hero carries the call to action; Download moves into the hero and the docs, since students arrive through a course link. The cloud has no site sections: course switcher and your avatar. Each header on the three places it would live: the landing page over the triangles, a docs page, and the cloud. Hover the links.
